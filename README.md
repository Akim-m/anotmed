# anotmed

A **medical image annotation assistant**. It suggests bounding boxes,
segmentation masks, and measurements on medical images; a radiologist verifies
them. It does **not** diagnose. Read [SAFETY.md](SAFETY.md) before real use.

## How it works

Three roles, each played by the right kind of model:

```
  DICOM ─▶ Localizer ──▶ boxes ──▶ Segmenter ──▶ mask ──▶ Measurement engine ──▶ mm values
           (MedGemma)              (MedSAM-2)              (pure numpy, deterministic)
              │                                                     │
              └────────────▶ Reporter (MedGemma) ─▶ draft text ◀────┘
                                        │
                                        ▼
                         Annotation (status: PENDING)
                                        │
                        radiologist accepts / edits / rejects
                                        │
                             accepted only ──▶ export (COCO / DICOM-SEG)
```

- **MedGemma** is a vision-language model — it proposes *where* findings are and
  writes the draft description. It does not produce pixel masks.
- **MedSAM-2** turns each box into a pixel mask. MedGemma's boxes are its prompts.
- **Measurements are computed from the mask by geometry**, never generated by the
  language model — so the numbers are reproducible and auditable.
- **Nothing is exported until a human accepts it** (enforced in `store.py`).

Two backends, chosen by one env var (`ANOTMED_BACKEND`):

| backend | needs | use |
|---|---|---|
| `stub` | CPU only | runs anywhere; classical CV standing in for the models; what the tests use |
| `medgemma+medsam` | GPU + weights | the real thing |

## Layout

```
anotmed/
  schema.py        domain types (the contract)
  measure.py       geometry engine — pure numpy, fully tested
  io_dicom.py      DICOM load/window/de-id, rendering, COCO export
  store.py         filesystem store + the accepted-only export gate
  pipeline.py      localize → segment → measure → report
  api.py           FastAPI service + serves the review UI
  web/review.html  the reviewer (upload, inspect, accept/reject, redraw, export)
  backends/
    base.py        Localizer / Segmenter / Reporter protocols
    stub.py        CPU backend (Otsu + connected components)
    medgemma.py    MedGemma adapter  ← integration point
    medsam.py      MedSAM-2 adapter  ← integration point
examples/make_sample_dicom.py   synthesize a test DICOM (no real data)
tests/             measure, safety invariant, pipeline, DICOM roundtrip, API
```

## Quickstart (WSL, CPU stub — no GPU needed)

> **OneDrive note:** this repo lives under a OneDrive-synced Windows path. For
> WSL, copy it to a native path first — `cp -r /mnt/c/Users/aydhi/OneDrive/Documents/ay/anotmed ~/anotmed`
> — and keep the venv and model cache out of OneDrive (sync + venvs = pain).

```bash
cd ~/anotmed
python -m venv .venv && source .venv/bin/activate
pip install -e ".[dev]"

# make a synthetic study and try the pipeline headlessly
python examples/make_sample_dicom.py sample.dcm

# run the tests (stub backend, no weights)
pytest -q

# start the service + review UI
anotmed-serve      # → http://127.0.0.1:8000
```

Open the UI, click **Analyze DICOM**, pick `sample.dcm`, and you'll see
suggestions with measurements. Accept one, then **Export accepted (COCO)**.

## Enabling the real models (GPU)

```bash
pip install -e ".[models]"

# MedSAM-2 / SAM2 install from git (not PyPI); follow their repo, then set:
export ANOTMED_BACKEND=medgemma+medsam
export ANOTMED_MEDGEMMA_MODEL=google/medgemma-4b-it
export ANOTMED_SAM_CHECKPOINT=/path/to/medsam2.pt
export ANOTMED_SAM_CONFIG=/path/to/sam2_hiera_s.yaml
anotmed-serve
```

Two integration points to confirm once, with weights loaded (they are
written-to-spec, not yet run against real MedGemma 1.5):

- **`backends/medgemma.py::_parse_boxes`** expects the Gemma-family `box_2d`
  JSON format (normalized 0–1000). If the released model card differs, adjust
  the prompt/parser there. Sanity-check by running one image through
  `MedGemmaLocalizer.propose` and printing the raw output.
- **`backends/medsam.py::_load`** uses the standard SAM2 image-predictor API. If
  your MedSAM-2 build names its predictor differently, adjust that one function.

## API

| method + path | does |
|---|---|
| `POST /api/studies` (multipart `file`) | upload DICOM, run pipeline, return pending suggestions |
| `GET  /api/studies` / `GET /api/studies/{id}` | list / fetch a study |
| `GET  /api/studies/{id}/image.png` | windowed display image |
| `GET  /api/studies/{id}/annotations` | all suggestions for a study |
| `GET  /api/studies/{id}/annotations/{aid}/mask.png` | mask overlay (RGBA) |
| `POST /api/studies/{id}/annotations/{aid}/review` | `{action: accept\|reject\|edit, box?, label?, note?}` — `box` re-segments |
| `POST /api/studies/{id}/export?format=coco` | export accepted only (409 if none) |
| `GET  /api/healthz` | liveness + active backend |

## Export

- **COCO JSON** — bbox, hull-polygon segmentation, plus an `anotmed` block with
  the mm measurements, provenance, status, and reviewer note. Working.
- **DICOM-SEG** — documented stub; needs the source series wired in (highdicom
  is in the `[seg]` extra).
